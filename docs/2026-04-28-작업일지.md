## 7. 추천 품질 개선 1차 구현

### 목표

- “비슷한 게임”이라는 기능명에 맞게 정말 유사성이 높은 게임만 반환하도록 추천 기준을 강화한다.
- 인기/평점 기반 보정으로 추천 결과가 왜곡되지 않게 한다.
- 유사 후보가 부족하면 억지로 개수를 채우지 않고 적게 반환하거나 빈 배열을 반환한다.

### 백엔드 변경

#### `GET /api/games/{id}/similar`

- 기존 장르 one-hot + 태그 multi-hot 코사인 유사도를 제거했다.
- 새 점수식을 적용했다.

```text
similarity =
  genreScore * 0.35
+ weightedTagScore * 0.50
+ keywordScore * 0.15
```

- `popularity`, `rating`은 추천 점수와 정렬 기준에서 제외했다.
- 정렬 기준을 아래 순서로 변경했다.
  - 유사도 내림차순
  - 의미 있는 태그 overlap 수 내림차순
  - 태그 유사도 내림차순
  - title 오름차순

### 태그 가중치 정책

- 태그 유사도는 weighted Jaccard 방식으로 계산한다.
- 태그별 문서 빈도 기반 IDF 보정을 적용해 흔한 태그의 영향력을 낮췄다.
- 핵심 플레이 특성 태그는 가중치를 높였다.
  - 예: `Souls-like`, `Roguelike`, `Deckbuilding`, `Turn-Based`, `Open World`, `Survival`, `Hack and Slash`, `Card Game`
- 약한 신호 태그는 낮은 가중치로 처리했다.
  - 예: `Single-player`, `Multi-player`, `Co-op`, `Free To Play`
- 플랫폼/기능성 태그는 유사도에서 제외했다.
  - 예: `Steam Achievements`, `Steam Cloud`, `Full controller support`, `Family Sharing`

### 후보 통과 조건

- 자기 자신은 항상 제외한다.
- 같은 장르 후보도 의미 있는 태그 overlap이 없고 설명 유사도도 낮으면 제외한다.
- 장르가 다른 후보는 더 엄격하게 제한한다.
  - 의미 있는 태그 overlap 2개 이상
  - 태그 유사도 0.50 이상
  - 설명 키워드 유사도 0.35 이상
- 최소 유사도 점수 미만 후보는 반환하지 않는다.
- 추천 결과 수를 억지로 채우지 않는다.

### 테스트 추가/수정

- 기존 “추천 결과 3개 반환” 기대값을 제거했다.
- 유사하지 않은 데이터에서는 빈 배열을 반환하도록 테스트를 수정했다.
- 강한 유사 신호만 추천되는 테스트를 추가했다.
  - 같은 장르 + 핵심 태그 overlap 후보 통과
  - 장르가 달라도 핵심 태그와 설명이 강하게 겹치면 통과
  - 같은 장르라도 `Single-player`, `Steam Achievements` 같은 약한/무시 태그만 겹치면 제외
  - 자기 자신 제외

## 8. Steam 수집 품질 개선

### 목표

- Steam 수집 시 `rating=4.5`, `popularity=90` 임시값을 더 이상 사용하지 않는다.
- Steam에서 직접 제공하지 않는 값을 실제 Steam API 응답을 기반으로 산정한다.
- 기존 프론트/백엔드 API 필드명은 유지한다.

### 확인 내용

- `appdetails` API에는 `rating`, `popularity` 필드가 직접 존재하지 않는다.
- `appdetails.ratings`는 사용자 평점이 아니라 연령/심의 등급이다.
- 평점 산정에는 Steam User Reviews API의 `query_summary`를 사용할 수 있다.
  - `total_positive`
  - `total_negative`
  - `total_reviews`
  - `review_score_desc`
- 인기 산정에는 `appdetails.recommendations.total`과 Steam Charts API 순위를 사용할 수 있다.

### 백엔드 변경

- `SteamService`에서 게임 저장 전 리뷰 요약 API를 호출하도록 변경했다.

```text
GET https://store.steampowered.com/appreviews/{appid}?json=1&filter=summary&language=all&purchase_type=steam&num_per_page=0
```

- `rating` 산정식을 적용했다.

```text
rating = total_positive / total_reviews * 5
```

- 리뷰가 없거나 리뷰 API 호출에 실패하면 `rating=0.0`을 저장한다.
- `popularity`는 0-100 점수로 산정한다.
  - `recommendations.total`을 로그 스케일 점수로 환산
  - Steam Charts `GetMostPlayedGames` 순위가 있으면 차트 점수와 비교해 더 높은 값을 사용
- 기존 `DEFAULT_RATING=4.5`, `DEFAULT_POPULARITY=90` 임시 기본값을 제거하고 각각 `0.0`, `0`으로 변경했다.
- 수집 대상 app id는 `featuredcategories`의 `top_sellers`, `new_releases`, `specials`를 중복 제거해 최대 30개까지 사용하도록 개선했다.

### 테스트

- 리뷰 데이터가 없으면 `rating=0.0`, `popularity=0`이 되는지 검증했다.
- `total_positive=80`, `total_reviews=100`이면 `rating=4.0`이 되는지 검증했다.
- `recommendations.total=10000`이면 로그 스케일로 `popularity=57`이 되는지 검증했다.
- Steam Charts 점수가 recommendations 기반 점수보다 높으면 차트 점수가 우선되는지 검증했다.

## 10. 프론트 LIST UX 보정

### 목표

- 태그 수가 많아질 때 LIST 페이지 필터 영역이 과도하게 길어지는 문제를 줄인다.
- 모바일에서 검색/필터/페이지네이션이 더 안정적으로 줄바꿈되도록 한다.
- 검색 결과 없음 화면을 더 명확하게 만든다.
- 페이지 수가 많아질 때 모든 페이지 번호를 한 번에 렌더링하지 않는다.
- `popularity`가 실제 순위가 아니라 0-100 산정 점수로 바뀐 점을 UI에 반영한다.

### 프론트 변경

#### LIST 검색/필터

- 검색 폼을 모바일에서 세로 배치, 데스크톱에서 가로 배치로 변경했다.
- 필터 영역을 하나의 도구 영역으로 묶고 상단에 `Clear all`을 배치했다.
- 태그는 기본 18개까지만 노출한다.
- 나머지 태그는 native `details/summary` 접기 영역의 “태그 더 보기” 아래로 이동했다.
- 현재 선택된 태그가 기본 18개 밖에 있어도 항상 보이도록 보정했다.

#### 검색 결과 없음

- 영어 문구를 한국어 문구로 변경했다.
- 현재 적용 조건을 결과 없음 메시지에 표시하도록 변경했다.
- `Clear filters`, `홈으로` 액션을 제공한다.

#### 페이지네이션

- 전체 페이지 번호를 모두 렌더링하던 방식을 제거했다.
- 현재 페이지 주변, 첫 페이지, 마지막 페이지만 보여주고 중간은 `...`으로 축약한다.
- 페이지네이션 컨테이너가 모바일에서 줄바꿈되도록 변경했다.

#### 인기 표시

- 기존 UI는 `인기 {value}위`로 표시했지만, 이제 `popularity`는 순위가 아니라 산정 점수다.
- LIST/DETAIL/유사 게임 카드의 문구를 `인기 점수 {value}`로 변경했다.

### 검증

- `npm run lint`: 성공
- `npm run build`: 성공
- 빌드 검증을 위해 H2 test profile 백엔드를 임시로 기동했다.

## 12. 코드 단순화 (simplify)

### 목표

- 프론트엔드는 이번 범위에서 제외한다.

### 변경 내용

#### `application.properties`

- `spring.datasource.password` 값에 trailing space가 포함되어 있어 DB 연결이 실패할 수 있는 버그를 수정했다.
  - 수정 전: `Dlrudalswns2@ ` (공백 포함)
  - 수정 후: `Dlrudalswns2@`

#### `SteamService.java`

- `fetchMostPlayedPopularityScores()` 내부에서 `java.util.Map`, `java.util.HashMap`을 full-qualified name으로 사용하고 있었다.
- 파일 상단에 `import java.util.HashMap;`을 추가하고 메서드 내부의 full-qualified 참조를 제거했다.

#### `GameService.java`

1. `searchGames()` 중복 인수 추출
   - `gameRepository.searchGames()` 7개 인수를 두 번 그대로 반복하던 out-of-range 페이지 재시도 로직을 `lowerSearch`, `normalizedSearchParam`, `aliasGenreParam` 로컬 변수로 추출했다.
   - 인수 목록 변경 시 한 곳만 수정하면 되도록 개선했다.

2. `normalize()` / `normalizeTagKey()` 중복 제거
   - 두 메서드가 동일한 `toLowerCase` + `replaceAll("[\\s\\p{Punct}]+", "")` 로직을 가지고 있었다.
   - `normalize()`가 `normalizeTagKey()`에 위임하도록 변경해 구현이 한 곳에서만 존재하게 했다.

3. `getSimilarGames()` target 태그 중복 정규화 제거
   - `scoreSimilarGame()`이 스트림 내에서 N-1번 호출되며 매번 `normalizedTagsOf(target)`를 재계산하고 있었다.
   - `getSimilarGames()` 외부에서 `targetTags`를 한 번만 계산해 `scoreSimilarGame()`에 전달하도록 변경했다.
   - `scoreSimilarGame()` 시그니처에 `Set<String> targetTags` 파라미터를 추가했다.

4. `keywordTokensOf()` stream 전환
   - 수동 루프를 `Arrays.stream().filter().collect(Collectors.toSet())`으로 교체했다.
   - `import java.util.Arrays`, `import java.util.stream.Collectors`를 추가했다.
