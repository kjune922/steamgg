# AGENTS.md

## 목적
이 디렉토리는 Next.js + TypeScript 기반 프론트엔드 앱이다.

현재 1차 MVP 범위는 아래 3개 페이지를 중심으로 한다.
- ROOT: 검색창, 인기 게임 일부 노출, 로그인 버튼 UI
- LIST: 검색 결과 목록, 필터, 정렬
- DETAIL: 게임 설명, 구매 링크, 유사 게임

루트 AGENTS.md의 공통 규칙을 먼저 따르고, 이 문서는 프론트엔드 작업에만 적용되는 세부 규칙을 정의한다.

## 현재 우선 범위
- ROOT 페이지 UI와 검색 진입 흐름
- LIST 페이지 검색 결과, 필터, 정렬
- DETAIL 페이지 상세 정보, 구매 링크, 유사 게임
- 백엔드 API와 맞는 타입 정의 및 화면 연결

## 프론트엔드 작업 원칙
- 기존 컴포넌트, 레이아웃, 스타일 패턴을 먼저 재사용한다.
- 새로운 UI 라이브러리는 꼭 필요하지 않으면 추가하지 않는다.
- 상태는 가능한 단순하게 유지한다.
- 검색과 필터 상태는 가능하면 URL query parameter와 맞춘다.
- API 응답 타입은 백엔드 계약과 일치해야 한다.
- 목업 데이터와 실제 API 응답 형식이 다르지 않게 유지한다.
- 요청 범위를 넘는 디자인 리뉴얼이나 구조 변경은 하지 않는다.

## UI 및 화면 규칙
- 모바일 390px, 데스크톱 1280px 기준으로 레이아웃이 깨지지 않아야 한다.
- ROOT, LIST, DETAIL 사이의 탐색 흐름이 자연스러워야 한다.
- 카드 UI에서는 제목, 이미지, 핵심 정보가 먼저 보이게 한다.
- DETAIL 페이지에서는 게임 설명, 구매 링크, 유사 게임 영역이 명확하게 구분되어야 한다.
- 로그인 버튼은 현재 MVP 범위에서는 UI만 구현하고 실제 인증 흐름은 건드리지 않는다.

## 파일 수정 원칙
- 관련 페이지와 공통 컴포넌트를 먼저 확인한 뒤 수정한다.
- 시각적 변경과 기능 변경은 가능하면 분리한다.
- API 연결 방식이 바뀌면 관련 타입 정의도 함께 점검한다.
- 하드코딩한 API 주소는 사용하지 않고 환경변수나 설정으로 분리한다.
- 범위 밖의 페이지나 컴포넌트는 필요 이상으로 손대지 않는다.

## 권장 작업 방식
- 수정 전 관련 페이지, 공통 컴포넌트, 타입 정의 구조를 먼저 파악한다.
- 낯선 영역은 먼저 읽기 전용 탐색으로 구조를 정리한 뒤 수정한다.
- 큰 시각적 변경이 있으면 docs/context-packs/에 의도와 영향 범위를 짧게 남긴다.
- 작업 종료 전 docs/continuity/current.md에 현재 상태와 다음 작업을 남긴다.
- 작업 전에 루트 DESIGN.md를 읽고 현재 프로젝트의 시각적 규칙을 먼저 확인한다.
- UI 작업 시 DESIGN.md를 우선 기준으로 따르고, 요청이 없으면 이를 벗어나는 스타일 변경을 하지 않는다.

## 검증
- 타입 에러가 없어야 한다.
- 빌드가 통과해야 한다.
- 주요 페이지 이동 흐름이 정상이어야 한다.
- 검색, 필터, 상세 진입이 깨지지 않아야 한다.
- 불필요한 console 로그와 임시 코드는 제거한다.
